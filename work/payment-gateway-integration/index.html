Payment gateway layer

FYB Technologies · independent clients  ·  2020  ·  Production

The problem

Every provider models a deposit differently, and all of them fail differently. Product teams should not have to care which one is behind a transaction.

What I built
  • One internal contract across card, bank transfer and crypto deposit providers.
  • Settlement reconciliation against provider statements, surfacing mismatches rather than swallowing them.
  • Per-provider retry and failure handling, so one gateway outage degrades instead of blocking deposits.
How it works

Payment providers agree on almost nothing. One returns a settled deposit synchronously, another acknowledges and settles by webhook minutes later, a third goes quiet and expects to be polled. Currencies, minimum amounts, fee models and error vocabularies all differ. Wire each provider straight into product code and those differences spread everywhere.

The fix is one internal contract that product code speaks, with an adapter per provider behind it. A deposit means the same thing on every path; failure modes are normalised so callers handle a small, known set rather than each provider's dialect. Resilience policies with Polly govern retries and timeouts per provider, so a single gateway degrading does not take deposits down with it.

Reconciliation runs against provider statements rather than trusting callbacks. Where the ledger and the provider disagree, the mismatch is surfaced for a human rather than quietly absorbed — in payments, a silent discrepancy is worse than a loud one.
