02 Payments Production

Payment gateway layer

Every provider models a deposit differently, and all of them fail differently. Product teams should not have to care which one is behind a transaction.

C# / .NET / SQL Server / Serilog
Project details
  • One internal contract across card, bank transfer and crypto deposit providers.
  • Settlement reconciliation against provider statements, surfacing mismatches rather than swallowing them.
  • Per-provider retry and failure handling, so one gateway outage degrades instead of blocking deposits.

03 Integration Production

Game provider aggregator

Each studio ships its own launch protocol, wallet callbacks and reporting format. Integrating them one by one would have spread provider quirks through the platform.

C# / .NET / ASP.NET Core / AWS SQS
Project details
  • Slots and live table games behind a single internal contract.
  • Idempotent wallet callbacks, so a repeated provider call cannot double-credit a player.
  • Per-provider adapters isolating protocol differences from platform code.

04 / How I work

Own it end to endincluding at 2am.

How I actually work, not a methodology I read about.

01

Understand the money

Start with what the transaction actually is, who reconciles it, and what happens when it fails halfway.

02

Draw the boundary

Decide where the service ends before writing it. Most production pain is a boundary drawn in the wrong place.

03

Instrument, then ship

If I cannot tell what a service is doing at 2am from its logs and traces, it is not finished.
